# 言語交換チャットPWA 設計書

最終更新：2026-10-27

## コンセプト

AIが相手の言語交換チャット。会話を続けながら、自分の文の間違いを毎回カードで直してもらう。

- 相手はAIなので、返信の間隔や途中離脱を気にしなくていい
- 恋愛RPではなく、性別・出身地・職業くらいの軽いペルソナを持つ話し相手
- 会話は止めず、矯正は吹き出しとは別のカードで出す
- 中国語をメインに作り込み、英語は同じアプリ内のモード切替で使う（中国語専用機能は省く）

## 言語モードと機能差分

共通機能をベースに作り、中国語モードにだけ専用機能を足す。データには最初から言語フィールドを持たせ、英語モードを後から差し込めるようにする。

| 機能 | 中国語 | 英語 |
| --- | --- | --- |
| 会話＋日本語訳（タップで表示） | ○ | ○ |
| 矯正カード（error / unnatural） | ○ | ○ |
| 間違いログ | ○ | ○ |
| 「何て言う？」（日本語で聞く） | ○ | ○ |
| 読み上げ（Web Speech API） | ○ zh-CN | ○ en-US / en-GB |
| レベル設定 | HSK 1〜6 | CEFR A2〜C1 |
| ピンイン表示 | ○ アプリ / モデル生成 | — |
| 声調の色分け | ○ | — |
| 簡体字 / 繁体字の切替 | ○ 表示切替 | — |
| 単語タップで意味表示 | 後回し | 後回し |

## 画面構成

4画面で足りる。

1. パートナー一覧：言語ごとにパートナーを並べる。作成・編集もここから
2. チャット：相手の吹き出し（訳はタップで開く）、自分の吹き出しの下に矯正カード、入力欄の横に「何て言う？」ボタン
3. 間違いログ：日付・パートナー・種類で絞り込み、復習済みにチェック
4. 設定：モデル選択、ピンインの表示と生成元、簡体字 / 繁体字、読み上げ速度

## パートナー設定項目

1パートナー＝1ペルソナ＋1言語。項目は少なめにして、作るのを面倒にしない。

| 項目 | 例 | 何に効くか |
| --- | --- | --- |
| 名前 | 陈宇 | 呼び方、ログの表示 |
| 言語 | 中国語 / 英語 | モードの決定 |
| 性別 | 男性 | 口調の自然さ |
| 年齢 | 27 | 話題の年代感 |
| 出身地・在住 | 成都出身、上海在住 | 食べ物、方言の口癖、地元ネタ |
| 職業 | 会社員（IT） | 雑談の種 |
| 性格・口調 | 落ち着いている、たまに冗談 | 返答のトーン |
| 趣味 | 火鍋、ゲーム | 相手からの話題振り |
| 英語の変種（英語のみ） | 米 / 英 | スペル、語彙、読み上げ音声 |

## 返答JSONスキーマ

毎ターンこの形で返させる。学習言語と日本語をフィールドで分けるので、2言語が混ざりにくい。

```json
{
  "corrections": [
    {
      "original": "我因该去",
      "fixed": "我应该去",
      "type": "error",
      "note_ja": "「因该」は誤字。正しくは「应该」"
    }
  ],
  "reply": "那你应该去试试！",
  "reply_ja": "じゃあ行ってみなよ！",
  "memory_hint": null
}
```

- corrections：配列。間違いがなければ空配列
- type：error（誤り）か unnatural（通じるけど不自然）
- reply は学習言語のみ、reply_ja は日本語のみ
- memory_hint：覚えておくべき新情報があれば一言。なければ null（記憶の要約の材料）
- pinyin：設定でモデル生成をONにしたときだけ追加（中国語専用機能を参照）

## 矯正ルール

矯正はユーザーの直前の発言だけを対象にし、会話の返事とは切り離す。

- 直すのは誤字、文法、語順、語の選択。句読点の全角半角やくだけた表記は見逃す
- 口語として自然な省略は直さない（unnatural にもしない）
- 1発言につき最大3件。細かすぎる指摘で会話が止まらないようにする
- 文全体を書き直すときは、original に元の文、fixed に直した文を入れる
- 相手は会話の中で間違いに触れない（矯正カードに任せる）
- 日本語や英語が混ざっていても、それ自体は誤りにしない

## 中国語専用機能

ピンインはアプリ側で生成するのを基本にし、設定でモデル生成に切り替えられるようにする。簡体字 / 繁体字も表示だけ切り替える。

- ピンインの生成元（設定で切替）
  - アプリ：JSライブラリ（pinyin-pro など）で生成。トークン代なし。ただし多音字（了・得・行 など）を誤読することがある
  - モデル：JSONに pinyin を追加。漢字1文字につき1音節、スペース区切りで返させる。文脈で多音字を読み分けられる
  - モデル生成の音節数が漢字数と合わないときは、そのターンだけアプリ側の生成に切り替える
- ピンイン表示：「常時 / タップ / オフ」の3段階。漢字の上にルビで出す
- 自分の発言にもアプリ側でピンインを付けて、声調の確認に使えるようにする
- 声調の色分け：1〜4声と軽声を色で区別（ピンイン表示時のみ）
- 簡体字 / 繁体字：保存は簡体字のまま、表示するときだけ変換（opencc-js など）。ピンインは簡体字の元データから付けるので影響しない
- 読み上げ：Web Speech API の zh-CN 音声。速度を設定で調整
- HSKレベル：プロンプトで語彙の目安を指定し、それを超える単語は1ターン1〜2語までにする

## メモリーと間違いログ

メモリーは「パートナーの記憶」と「間違いログ」の2種類だけで、どちらもパートナー単位で持つ。

**パートナーの記憶**：相手が覚えているユーザーの情報（仕事、予定、前回の話題など）。箇条書き20行程度に収める。

1. 毎ターン、memory_hint があれば一時リストに溜める
2. 10ターンごと（またはチャットを閉じたとき）に、安いモデルで「今の記憶＋一時リスト＋直近の会話」から記憶を書き直す
3. 次のターンからシステムプロンプトに差し込む
4. 記憶はパートナー編集画面で見て、手で直せるようにする

**間違いログ**：corrections を受け取るたびに1件ずつ自動保存。1件の中身は日時、パートナー、言語、元の文、直した文、種類、解説、復習済みフラグ。

**保存先**：VPS上のSQLite（既存PWAと同じ構成）。記憶の要約もサーバー側で実行する。

| テーブル | 主な列 |
| --- | --- |
| partners | id, name, language, persona（JSON）, level, created_at |
| messages | id, partner_id, role, content（JSON）, created_at |
| partner_memory | partner_id, body, pending_hints, updated_at |
| mistakes | id, partner_id, language, original, fixed, type, note_ja, reviewed, created_at |
| settings | key, value |

## システムプロンプト構成

上から順に組み立てる。変わらない部分を前に置くと、プロンプトキャッシュが効きやすい。

1. 役割：言語交換アプリの相手。ユーザーは日本語話者で、{言語}を学習中
2. 会話ルール：返信は1〜3文。ときどき質問を返して会話を続ける。説教しない。恋愛的な展開にしない
3. 矯正ルール：「矯正ルール」の内容をそのまま
4. 出力形式：JSONスキーマ。JSON以外は出力しない
5. ペルソナ：パートナー設定の各項目
6. レベル：{HSK / CEFR}。語彙と文の長さを合わせる
7. 記憶：パートナーの記憶（毎回変わる部分）

「何て言う？」は別の短い呼び出しにする。日本語の文を渡し、言い方の候補1〜2個と一言の解説を返させる。

## モデルと通信

既存PWAと同じくOpenRouter経由で、呼び出しはVPSのサーバーから行う。APIキーはサーバー側にだけ置く。用途ごとにモデルを分け、設定画面で切り替えられるようにする。

| 用途 | 候補 |
| --- | --- |
| 会話＋矯正 | Claude Sonnet / DeepSeek |
| 記憶の要約 | 安いモデル（Haiku など） |
| 何て言う？ | 会話と同じモデル |

- JSONスキーマ指定に対応したモデルではそれを使い、未対応のモデルはプロンプトでの指示だけにする
- パースに失敗したら1回だけ再試行。それでもだめなら生テキストを吹き出しに出し、会話は止めない
- 送る履歴は直近20往復程度。それより前は記憶に任せてトークンを抑える
